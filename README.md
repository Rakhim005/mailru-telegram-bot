# Уведомления о новых письмах Mail.ru в Telegram

Бот раз в 60 секунд проверяет папку «Входящие» ящика Mail.ru по IMAP
(`imap.mail.ru:993`, SSL) и пересылает в группу Telegram каждое новое письмо:
отправителя, тему, дату, текст письма и вложенные файлы.

## Как это работает

- Первое сообщение — заголовок письма и его текст. Если письмо в HTML, оно
  переводится в обычный текст. Длинный текст делится на несколько сообщений
  (до ~14 000 символов, дальше обрезается с пометкой).
- Вложения приходят отдельными файлами ответом на это сообщение. Пересланные
  письма прикладываются как `.eml`. Картинки из оформления письма (логотипы,
  подписи) не пересылаются.
- Telegram не даёт ботам отправлять файлы больше 50 МБ — о таком файле придёт
  предупреждение, а сам файл нужно открыть в почте.
- За одну проверку обрабатывается не больше 10 писем, остальные — при следующей.

- Бот подключается к ящику **только для чтения** и не помечает письма прочитанными.
- Последний обработанный UID письма хранится в `last_uid.txt` — после перезапуска
  уведомления не дублируются.
- При **первом запуске** бот только запоминает текущее состояние ящика и не
  присылает старые письма. Уведомления придут для писем, полученных после запуска.
- Логи пишутся в консоль и в файл `bot.log`.

## 1. Подготовка

### Пароль приложения Mail.ru

Обычный пароль от почты для IMAP не подойдёт.

1. Откройте Mail.ru → **Настройки → Безопасность → Пароли для внешних приложений**.
2. Создайте пароль (доступ: «Полный доступ к Почте» или «Только IMAP/SMTP»).
3. Убедитесь, что в **Настройки → Почтовые программы** включён доступ по IMAP.

### Telegram-бот и группа

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и скопируйте токен.
2. Добавьте бота в нужную группу.
3. Узнайте ID группы: напишите в группу любое сообщение и откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — ищите `"chat":{"id":-100...}`.
   Если ответ пустой, временно отключите у бота Privacy Mode в @BotFather
   (`/setprivacy` → Disable) или упомяните бота в сообщении.

## 2. Установка

Нужен Python **3.10–3.13**. На Python 3.14+ зависимости aiogram (`aiohttp`,
`pydantic-core`) пока не имеют готовых сборок, и pip пытается компилировать их
из исходников — без Visual C++ Build Tools это падает с ошибкой.

Все команды выполняются **в папке проекта** (там, где лежит `bot.py`).

### Windows

На Windows команды `python` и `pip` часто не находятся (`pip : The term 'pip' is
not recognized`). Используйте лаунчер `py` с явной версией:

```bash
py -3.13 -m venv .venv
```

```bash
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### Linux / macOS

```bash
python3 -m venv .venv
```

```bash
.venv/bin/python -m pip install -r requirements.txt
```

## 3. Настройка

Скопируйте `.env.example` в `.env` и заполните значения:

| Переменная            | Описание                                   |
|-----------------------|--------------------------------------------|
| `TELEGRAM_BOT_TOKEN`  | Токен бота от @BotFather                   |
| `TELEGRAM_CHAT_ID`    | ID группы (обычно начинается с `-100`)     |
| `MAILRU_USER`         | Адрес ящика, например `name@mail.ru`       |
| `MAILRU_APP_PASSWORD` | Пароль для внешнего приложения             |

Файл `.env` содержит секреты — не публикуйте его (он уже в `.gitignore`).

## 4. Запуск

Windows:

```bash
.venv\Scripts\python.exe bot.py
```

Linux / macOS:

```bash
.venv/bin/python bot.py
```

Остановка — `Ctrl+C`.

Чтобы заново начать отсчёт с текущего состояния ящика, удалите `last_uid.txt`.

## Работа через GitHub Actions (бесплатно, без своего компьютера)

Файл `.github/workflows/check-mail.yml` запускает `python bot.py --once`
каждые 5 минут на серверах GitHub. Режим `--once` — одна проверка и выход.
После проверки `last_uid.txt` сохраняется обратно в репозиторий.

1. Секреты задаются в репозитории: **Settings → Secrets and variables → Actions**
   (те же четыре переменные, что в `.env`), или командой из папки проекта:

   ```bash
   gh secret set -f .env
   ```

2. Ручной запуск: вкладка **Actions → Проверка почты → Run workflow**.

Особенности:

- GitHub не гарантирует точное время: запуск может опоздать на 5–30 минут.
- В публичном репозитории логи запусков видны всем, поэтому в GitHub Actions бот
  не пишет в лог имена файлов и имя бота. Пароли и токены GitHub скрывает сам.
- Если в репозитории 60 дней не было изменений, GitHub отключает расписание.
  Обычно это не грозит: каждое новое письмо обновляет `last_uid.txt`. Если
  отключилось — включите на вкладке Actions.
- Не запускайте бота одновременно и на компьютере, и в GitHub — будут дубли.

## Частые ошибки

- **`pip : The term 'pip' is not recognized`** — используйте `py -3.13 -m pip ...`
  или pip из виртуального окружения (`.venv\Scripts\python.exe -m pip ...`).
- **`Microsoft Visual C++ 14.0 or greater is required` / `link.exe not found`** —
  слишком новый Python. Установите Python 3.13 и пересоздайте `.venv`.

- **`AUTHENTICATE failed` / ошибка входа IMAP** — используется обычный пароль вместо
  пароля приложения, либо IMAP выключен в настройках почты.
- **`chat not found`** — неверный `TELEGRAM_CHAT_ID` или бот не добавлен в группу.
- **`Unauthorized`** — неверный `TELEGRAM_BOT_TOKEN`.
